# C5: content and preview UI

## TLDR

Chronicle now has a UI: a content tab (submissions, drafts board, import,
editor) and a preview tab, server-rendered by the api process at `/`, with
no login of its own (ADR 014, ADR 004). The UI authenticates its own writes
into the store using the `ui` token, read fresh from
`data/state/ui_token.txt` on every request, so revoking that token on
`/admin/tokens` disables the whole UI immediately. Every version, event, and
commit the UI produces is authored `scott`. `make check` is green (320
tests). Verified on a fresh-volume compose stack against the real blog
clone: digested 347 posts, imported, edited, saved, previewed, requested a
revision, saved a second version as a separately issued `ghostwriter`
token, viewed both authors in version history and their diff, and produced
and viewed a 409 conflict from a stale save. An adversarial review of the
diff found six real issues (one critical: stored XSS reachable by any
consumer token into Scott's own browser); all six are fixed on this branch
with regression tests.

## What changed

- **UI backend** (ADR 014): `chronicle/api/ui_deps.py`,
  `chronicle/api/ui_templates.py`, `chronicle/api/routes/ui.py`. In-process
  calls into `Store`, not loopback HTTP; the ADR covers the operational
  tradeoff (token rotation, hop cost, audit trail).
- **Content tab**: submissions queue and detail page (create draft, discard);
  drafts board filterable by status with claim/PR/preview/flag badges;
  import page with server-side search over `/v1/posts`; editor with
  frontmatter fields, a body textarea with a sanitised client-side markdown
  preview, image upload/detach, claim indicator, action buttons driven
  directly off `transitions.DRAFT_TRANSITIONS` (no second table), version
  history with a unified diff between any two versions, and the feedback
  log.
- **Conflict handling**: a stale save never overwrites. It renders a 409
  page: the server's diff summary (recomputed fresh against the draft's
  actual current version, not a possibly-stale cached one), the current
  version reloaded into the save form, and the visitor's full attempted
  frontmatter and body in a second, read-only pane.
- **Preview tab**: every draft with a built preview (link, build time, wall
  seconds, toolchain drift), a rebuild button, and a run log page for any
  run id.
- **Banner**: `CHRONICLE_UI_BANNER` (default on) shows "internal-only and
  unauthenticated" on every content and preview page.
- **Vendored**: `marked` v12.0.2 (MIT) for the live preview pane, real
  upstream bytes fetched from jsdelivr, licence in `THIRD_PARTY.md` and the
  file's own header. Everything else under `chronicle/api/static/` is
  original.
- **Tests**: `tests/test_ui.py`, 30 tests: rendering across every draft
  status (parametrised), submissions, import search, the conflict view
  (diff summary and both panes), version diffs, reserved actions landing on
  `scott`, image upload 413/415 parity with the API, the preview tab and run
  log, banner toggle, CSRF refusal (including the `null`-origin case), and a
  blanket "no token value in any rendered page" check.

## Adversarial review

One review subagent, given only `git diff main...HEAD` and the stated
scope (content/preview UI, out of scope: conversion, image paths,
publisher), found six issues. All six are real and fixed on this branch,
each in its own commit citing the finding:

1. **Stored XSS (critical).** The live preview pane assigned
   `marked.parse(textarea.value)` straight into `innerHTML` with no
   sanitisation. Since a draft's body can be written by any consumer token
   via `PUT /v1/drafts/{id}`, and Scott's own browser is what later renders
   it in the editor, this was a contributor-token to ui-token privilege
   escalation: a crafted body executes same-origin the moment Scott opens
   the draft, with reach to every reserved action. **Fixed**: `ui.js` now
   runs the parsed HTML through a small hand-written DOM sanitiser
   (strips script-bearing tags, `on*` attributes, `javascript:` URLs)
   before it touches the DOM.
2. **Reflected XSS (high).** The rebuild-failure page spliced an unescaped
   draft id (via the store's own 404 message) into a raw `<p>`. **Fixed**:
   removed the second, unescaped copy; the page's own `notice` mechanism
   already escapes.
3. **CSRF via `Origin: null` (high).** `check_same_origin` parsed the
   header with `urlsplit`, and a sandboxed iframe's literal `"null"` value
   parses to an empty netloc, which fell through the same branch as "no
   header sent" and let a cross-origin sandboxed iframe submit every
   state-changing form. **Fixed**: a present-but-unresolvable Origin or
   Referer is now always refused; only a genuine absence of both passes.
4. **`javascript:` URL in submission materials (medium).** A submission's
   material `url` is unvalidated input; `html.escape` alone left the scheme
   intact, so it rendered as a clickable link that ran on click. **Fixed**:
   only `http`/`https` schemes are ever linked; anything else renders as
   inert text.
5. **Conflict-view correctness (low).** The diff summary was computed
   inside `save_draft`'s lock and could describe an older version than the
   one the reloaded form actually showed if a second save landed in
   between; the attempted-text pane only kept title and body, dropping any
   attempted tag/date/summary edits. **Fixed**: the diff is recomputed
   fresh against the draft's actual current version when the conflict page
   renders, and the full attempted frontmatter is shown.
6. **Action-button/guard drift (low).** The re-approve button rendered
   purely off `transitions.DRAFT_TRANSITIONS`, which cannot see
   `Store.act_on_draft`'s separate refusal to re-approve while a publish PR
   is already open (409 `publish_pr_open`); the button 409ed on every click
   until the PR closed. Related: `draft_save` treated every 409 as the
   stale-version conflict, but `publish_pr_open` is also a 409 with nothing
   meaningful to diff. **Fixed**: the button renderer takes a
   `publish_pr_open` flag, and `draft_save` branches on `exc.code` before
   treating a 409 as the conflict-view case.

Nothing from the review was judged invalid; all six were confirmed against
the actual code and fixed.

## Not exercised

- Approve, unpublish, and republish were deliberately not clicked in the
  live check (C4's covered ground with mocks; no real GitHub App exists in
  this environment).
- Reconciliation flags on the drafts board were exercised with fixture data
  in `tests/test_ui.py`, not against a live reconciliation run (no real
  drift scenario was available in the live check's short window).
- A second api replica: the UI adds no new concern here beyond what ADR 013
  already carries for the publisher and watcher.

## Deviations from spec, with why

- The spec's UI deliverable describes "republish" as a distinct button
  label; the domain has no separate `republish` action, only `approve`
  reused for a draft that has already published once. The UI shows
  "republish" instead of "approve" exactly when `draft.published` is
  already set, rather than adding a second action.
- A CSRF door (`check_same_origin`) was added beyond the spec's explicit
  text, because "no session, no login" does not mean "no state-changing
  request forgery risk" on a network-reachable form; ADR 014 covers the
  reasoning.

## Not done, noticed

- No CSP header is set anywhere in the api process; one would be useful
  defence-in-depth on top of the sanitiser fix above, but is a broader
  change than this round's scope (it would need auditing every inline
  style/script this UI and the admin pages use).
- Attached images can be detached and re-uploaded but not re-labelled by
  role in place; changing a feature image to inline (or back) needs a
  detach and re-upload.
- The drafts board, submissions list, and import list have no pagination;
  fine at this round's scale, worth flagging before a real instance
  accumulates hundreds of drafts.
- `ci/compose-smoke.sh` still is not wired into CI (carried over from C3/C4,
  AGENTS.md already notes this; C5 adds no fixture-repo dependency beyond
  what C3 already needed).
